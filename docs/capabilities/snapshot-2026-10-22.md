## 1. One-page summary

### What works today (verified, on named hardware only)

1. **UCompute Run: local AI inference.** A small open model in GGUF format runs on the computer itself through a pinned llama.cpp engine (release b11609). It streams output, can be cancelled, checks that a model fits in memory before loading it, verifies every download against a pinned SHA-256 hash and offers a local OpenAI-compatible API. All of this is verified on one Apple M2 MacBook Air running macOS 26.2. A Windows 11 laptop (Intel Arc 140V GPU) and a second Mac (Apple M2 Pro; that platform remains PLANNED per §27.1) have also run it.
2. **UCompute Mesh: private remote execution between your own paired devices.** Two devices on one local network find each other (on a network that passes local discovery, such as a home network or phone hotspot; otherwise they pair by address), pair with a short code and can then send a whole request to run on the other device. The connection is encrypted and both ends authenticate. Verified between a Mac and a Windows laptop through the background service (daemon). Separately, development builds of the desktop apps were paired through their windows in a 2026-10-19 demonstration (section 3.2, last row); the Mac-side permission and the Mac-to-Windows request used the Mac's local API, and UI pairing (F-10-05) remains IMPLEMENTED_UNVERIFIED.
3. **Safe defaults.** By default no inference request leaves the device. Another device can receive work only after the user pairs it and allows it. A revoked device was cut off within a tenth of a second in two-machine tests, and in tests and both two-machine runs, audit logs contained no prompt or response text.

### What does not exist (never imply it does)

| Distinction | What exists | What does **not** exist |
|---|---|---|
| Remote inference vs. pooling | Whole-request remote execution (spec Mode B). Each request runs entirely on one device the user picks | Splitting or partitioning one model across devices, pooling memory or GPUs, running a model too big for any single device. Pooling is not implemented or verified (Gate D; F-03-* NOT_STARTED) |
| Private Mesh vs. public Swarm | A private Mesh of devices the user paired, on one local network | An open or public network, contributing to strangers, a public relay, connections across the internet (Swarm/Mode F disabled; F-02-06 NAT traversal and relay NOT_STARTED; Gate F not verified) |
| Planned credits vs. billing | A binding design principle for future compute credits (D-019, spec §26.5) | Credits, earning, purchases, prices, fees, billing, payments, payouts, trusted-access allowlists, sharing modes. U-05 and F-07-01..11 are NOT_STARTED; F-07-12 (token-incentive feasibility) is IN_PROGRESS as research only. No §26.5 stage is authorized |
| Development builds vs. releases | Development builds: macOS ad-hoc signed and not notarized, Windows without a code-signing certificate. The project installed them on its 3 test machines | Any public release, download, signed or notarized installer, auto-update or alpha/beta cohort (B-007, B-008; Gate G incomplete; §31: no cohort started) |
| Protocol aspiration vs. interoperability | One implementation's peer protocol, EXPERIMENTAL. A local HTTP API that the official OpenAI client libraries work against | A second, independent implementation of the peer protocol, a stable protocol version, independently verified interoperability (U-01 NOT_STARTED; B-018) |

### Coverage at a glance

- **Three physical machines in total:** an Apple M2 MacBook Air (macOS 26.2), an Apple M2 Pro MacBook Pro (macOS 15.7.9) and an HP laptop with an Intel Core Ultra 7 258V and Arc 140V (Windows 11 Home 26200).
- **No platform is SUPPORTED** (spec §27.1). macOS 26.2 on Apple M2 and Windows 11 on Arc 140V are EXPERIMENTAL. Other Apple Silicon, including the M2 Pro on macOS 15.7.9, is PLANNED, as are Linux, NVIDIA/AMD GPUs, Intel Macs, mobile and browsers.
- **No throughput figure is a performance measure.** Every tokens-per-second number below comes from tiny models (stories15M, SmolLM2 360M, Qwen2.5 0.5B) and is a *path check*: it shows that the path works, not how fast it is.
- **Still pending (why this is a draft):** a Windows retest of the 2026-10-21 fixes, including the firewall consent step and pairing started on Windows; the Mac-to-Mac pairing checks that failed (one test-setup error, one with cause not established) and the restart and crash-cleanup checks invalidated when the tester's Mac slept; and the Mac-side steps done through the app window. Until those runs are committed, the public claims rest on the 2026-10-18/19 evidence.
- **What the site can use now:** sections 8 and 9. They rest only on evidence committed by 1004b3b. Pending runs can add claims or remove section 9 rows. They withdraw a section 8 claim only if a retest shows a regression, and a new snapshot would say so.

## 5. Planned (committed scope or direction; none implemented)

106 ledger rows are NOT_STARTED. None of the following exists in code; dates are not set.

- **Pooling and partitioning (Gate D):** splitting one model across devices, distributed memory, activation transfer, pipeline or tensor parallelism, peer failure recovery (F-03-01..12; Modes C/D/E).
- **Automatic scheduling:** feasibility filtering, placement, the local-versus-distributed decision (F-04-*). Today the **user picks the target device explicitly**, and no scheduler component exists (§26.1).
- **UCompute Swarm (Mode F):** an opt-in open network with contribution, isolation and sandboxing (F-06-08), relay and NAT traversal (F-02-06), public discovery, reputation and fraud controls. It stays disabled until Gate F.
- **UCompute Cloud (Mode G):** an optional managed service. No paid service is authorized.
- **Compute credits (D-019, §26.5, U-05, F-07-01..11, X-05..07, I-03; F-07-12 is research only):** one balance, sharing modes (private, donate, share for credits; default off), trusted-access allowlists, a self-compute exclusion, a published fee, backed issuance. The stages run 0 (non-monetary laboratory), 1 (usage billing), 2 (purchasable balances) and 3 (transfer or payout), and **none is authorized**. Real-money functions need counsel and owner authorization (B-006, F-07-11). No cryptocurrency or blockchain is required or implemented. Self-hosted credit accounting, cross-network settlement and ledger federation are outside committed scope. Every price, fee or sustainability figure is a strategic hypothesis (§29.4).
- **Open contracts:** an independently implementable peer protocol (U-01), a versioned workload contract (U-02), a machine-checkable compatibility matrix (U-03), integration by independent developers (U-04), Python and TypeScript SDKs (F-09-05).
- **Product:** automatic updates with rollback (F-10-07), a mobile companion (F-10-12), resource-contribution controls (F-10-08), multimodal, LoRA and speculative decoding (F-01-09..11), peer-assisted model distribution (F-05-05..12), offline-first LAN operation with no internet (X-20).
- **Platforms (§27.1, PLANNED):** other Apple Silicon and Intel Macs, Linux x64/ARM64, Windows ARM64 execution, NAS, Android, iOS (always-on provider UNSUPPORTED), browser, cloud VMs, NVIDIA/CUDA and AMD/ROCm.

## 6. Known limitations

- **Hardware and OS coverage.** Three machines: Apple M2 on macOS 26.2, Apple M2 Pro on macOS 15.7.9, and Intel Arc 140V on Windows 11 Home 26200. There is no Linux host (B-004) and no mobile device (B-003). There are no NVIDIA, AMD or Intel Mac results. The Mac-M2Pro evidence covers the packaged app and a partial Mesh run only. No platform is SUPPORTED.
- **Small models only.** The development Mac has 8 GB (B-010). Inference evidence uses stories15M, stories260K, SmolLM2 360M and Qwen2.5 0.5B; the largest model measured, for memory planning only, is Qwen2.5 1.5B q4_k_m. Memory estimates are calibrated for llama.cpp b11609 on Apple Silicon.
- **One local network.** Mesh evidence covers two devices on the same Wi-Fi network or phone hotspot. There is no relay, no NAT traversal and no path across the internet (F-02-06 NOT_STARTED).
- **Internet on first run.** The engine and models are downloaded on first use. With networking switched on (off by default), a device announces itself on the local network for discovery and pairing. Operation with no internet is untested (X-20 NOT_STARTED).
- **Networks that drop multicast.** On eduroam, automatic discovery fails because the network does not pass mDNS between clients; the OS's own mDNS tools fail there too. Pairing by address and remote execution still worked there. Discovery was verified on a phone hotspot.
- **Windows Firewall.** The peer port was allowed on Private networks only, and the owner had to set the laptop's network profile to Private. Pairing started *from* Windows is dropped by the firewall (2026-10-19). The consent step that adds a scoped rule is implemented but has never run on Windows.
- **macOS firewall (suspected).** One Mac-to-Mac pairing failure on 2026-10-21 may come from the macOS application firewall blocking a newly built, ad-hoc-signed app. The cause is not established.
- **Unsigned or ad-hoc builds.** macOS builds are ad-hoc signed and not notarized, so `spctl` rejects them and a downloaded copy needs "Open Anyway" once. Windows builds carry no code-signing certificate (B-008).
- **No public release.** There is no binary download, no WP-08 release record, no executed CI pipeline, no alpha or beta cohort and no published source (B-007, Gate G, §31).
- **Fixture numbers are path checks.** stories15M tok/s figures say nothing about real-model performance: the 15M fixture even runs faster on CPU than on Metal. The fixture's weight license is unverified, so it is never redistributed (B-011). The 0.5B and 360M numbers come from 3 runs on one machine, not a controlled study.
- **Test hosts sleep.** The tester's Mac went to sleep twice during the 2026-10-21 run. The checks that ran while it slept are marked invalid and must be repeated. Nothing has been tested about the product's own behaviour across sleep and wake.
- **Load-sensitive results.** The 2026-10-21 tests on Mac-M2 ran at load average 7–12 from other processes. One latency bound (F-06-04) fails there and passes on a quiet machine.
- **Transport privacy only.** Encryption protects traffic between paired devices. The device that runs a request necessarily processes the prompt, so there is no confidential-computing or provider-blind execution (F-06-11 research only). The packet-capture proof is SINGLE-HOST; no LAN capture was taken.
- **Mixed build provenance in the demonstration.** Both 2026-10-19 apps (Mac 5f0c580, Windows caf1497) predate the 2026-10-21 fixes. The Windows app showed macOS wording ("This Mac"); this was changed in 6ab9f8b (unit tests only; not yet retested on Windows).
