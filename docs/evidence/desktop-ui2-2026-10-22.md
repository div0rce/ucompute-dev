# Desktop UI 2.0: implementation, reviews and tests (2026-10-22)

**SINGLE-HOST and unit evidence only.** The redesigned desktop app was built from `docs/design/desktop-ui-2-plan.md` and verified with the automated suites and a dev build in a browser against a scratch daemon on this Mac (temporary data folder, mDNS off, networking off). Packaged macOS and Windows apps, screen readers and the physical two-machine checks (plan §5.5 steps 4-7) are still to do.

## What changed

- **App:** a computing-network control center in the style of a qBittorrent-like client: a persistent rail (Dashboard, Devices, Models, Jobs, Chat, Activity, Settings), contextual toolbars, sortable dense tables (APG grid with cell focus and a column chooser), a resizable inspector with tabs, and a status bar fed only by real API fields. Chat stays fully functional as one section. Brand: charcoal, deep green and lime tokens, light and dark, contrast enforced by a test. Icons: a 44-glyph Lucide subset (ISC licence file included); the brand mark is original. Window and rail say "UCompute"; bundle, installer and data paths stay "Common" (D-018).
- **Data honesty rules enforced in code and tests:** a store keeps its last good data and shows "Not updated since" instead of presenting it as live; a slow service reads "Busy (not answering)", not "Not running"; a cached mDNS record never makes a device connected; unknown values read "Not known" or "—", never a definite state; every performance figure says what was measured, where and over which window; no credits, Swarm or Cloud controls (D-019: none exists).
- **Backend additions (plan §4):** E0 user-facing strings; E1 peer capabilities and connection details in `GET /api/peers` (hardware strings capped); E2 non-blocking engine state with `loaded_for`; E3 `GET /api/jobs` job registry with live token counts and no prompt or completion text; E4 audit `peer_lost` for involuntary losses only; E5 `POST /api/peers/{id}/disconnect` with an in-memory hold enforced in the transport for every path, including `common run --peer`, released by connect or unpair, read by older builds as `peer_held`.

## Reviews

- Build workflow: foundation and backend agents, four section agents in parallel, an integrator. One section agent (Devices) finished its code but timed out before reporting; a separate check compared Devices with the plan and found 16 gaps, all fixed.
- UX, security and data-honesty reviews: 29 findings confirmed by independent skeptics (2 high: the rail badge and Chat destinations counted devices as connected from stale data; a backend contract test compared fixtures with a never-connected peer). All fixed with tests; a mutation script showed every frontend fix's test fails when the fix is undone. Remaining low items are listed below.

## Commands and results (owner's Mac, Apple M2, macOS 26.2, load average 7-12)

- `cd apps/desktop && caffeinate -i pnpm test --maxWorkers=2` → 33 files, **420 passed, 0 failed** (a first run had 3 stall timeouts from the Mac sleeping; they pass on re-run). `npx tsc --noEmit` and `pnpm build` clean; the production bundle contains no axe code.
- `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings` → clean.
- `caffeinate -i env COMMON_HOME=$PWD/.common COMMON_REQUIRE_FIXTURES=1 COMMON_MDNS=0 cargo test --no-fail-fast` → **431 passed, 2 failed**, 2 ignored. The two failures are `sigterm_/sigint_mid_generation_stops_and_exits_130` (exit after 2.4 s against a 2 s bound under load); rerun three times alone: 3/3 pass each. Investigated 2026-10-22 (entry "Signal-exit timing" in docs/VERIFICATION.md): environmental (memory pressure), not a reliability defect, and the test's bound was tighter than the design guarantees; fixed in the test.
