# Desktop UI 2.0: implementation, reviews and tests (2026-10-22)

**SINGLE-HOST evidence only: three sets, all on this Mac.** The redesigned desktop app was built from `docs/design/desktop-ui-2-plan.md` and checked in three ways:
1. The unit and automated suites, plus screenshots of a dev build in a browser against one scratch daemon (temporary data folder, mDNS off, networking off). See "Commands and results".
2. Plan §5.5 step 3: the dev build in a real browser against two paired scratch daemons on loopback ports (networking on, mDNS off). See "Browser accessibility, keyboard and narrow-window checks".
3. The packaged macOS app built at d9d8067 and checked by `verify_packaged_app.py` (part of plan §5.5 step 4). See "Packaged macOS app".

The fixes of a later review are unit evidence only ("Review fixes"). What is still open is listed under "Open": the rest of step 4, the Windows packaged app, VoiceOver and NVDA, and the physical two-machine checks.

## What changed

- **App:** a computing-network control center in the style of a qBittorrent-like client: a persistent rail (Dashboard, Devices, Models, Jobs, Chat, Activity, Settings), contextual toolbars, sortable dense tables (APG grid with cell focus and a column chooser), a resizable inspector with tabs, and a status bar fed only by real API fields. Chat stays fully functional as one section. Brand: charcoal, deep green and lime tokens, light and dark, contrast enforced by a test. Icons: a 44-glyph Lucide subset (ISC licence file included); the brand mark is original. Window and rail say "UCompute"; bundle, installer and data paths stay "Common" (D-018; since D-021, 2026-10-22, UCompute is the product's name and Common its former name, and code identifiers stay `common` for now).
- **Data honesty rules enforced in code and tests:** a store keeps its last good data and shows "Not updated since" instead of presenting it as live. As committed in 1860196 this held for the tables only. Since the review fixes (listed under "Review fixes" below) it also holds for the inspectors (the Devices Overview and Connection tabs, and the Jobs Overview of an active job) and for the privacy mode (status bar and Settings), now a polled store like the others. A slow service reads "Busy (not answering)", not "Not running"; a cached mDNS record never makes a device connected; unknown values read "Not known" or "—", never a definite state; every performance figure says what was measured, where and over which window; no credits, Swarm or Cloud controls (D-019: none exists).
- **Backend additions (plan §4):** E0 user-facing strings; E1 peer capabilities and connection details in `GET /api/peers` (hardware strings capped); E2 non-blocking engine state with `loaded_for`; E3 `GET /api/jobs` job registry with live token counts and no prompt or completion text; E4 audit `peer_lost` for involuntary losses only; E5 `POST /api/peers/{id}/disconnect` with an in-memory hold enforced in the transport for every path, including `common run --peer`. The hold ends with Connect, unpair, revoke, turning networking off and on, or a service restart. Since the review fixes, a Sharing change keeps it. The held device reads the refusal as `peer_held` only if its build has E5. Older builds, such as the caf1497 Windows app in `mesh-physical-2026-10-22-eduroam.md`, read it as `peer_lost` ("closed by peer") and keep redialling with backoff. Since the review fixes (protocol minor 1), revocations still cross a hold: each time the held device dials, the two exchange the revocations due at the other before the close, so delivery waits for that device's next redial (backoff at most 300 s). That needs both devices on minor 1: every build committed so far, including the packaged apps above and the 593d4ea Windows installer, is minor 0 and gets the close at once, with no exchange. Known limit: two devices that hold each other exchange nothing until one of them connects.

## Review fixes (2026-10-22, after 245fd14): unit evidence only

A cross-cutting review of af3e37c..245fd14 confirmed 37 findings (2 high: a Sharing change silently ended every hold). The fixes that change what this app shows or sends are listed here; none is in a packaged build yet (the macOS app above was built at d9d8067, the Windows installer at 593d4ea):
- Inspectors and privacy mode follow the data-honesty rule (see "What changed"). The Activity table in the Devices inspector dims its rows while the Devices frame is busy or stale; it has no live columns, so nothing is blanked.
- A device this computer disconnected reads "Can use this computer: No · disconnected by you"; before the first status read, the status bar and Chat no longer say "no devices connected" or "No model loaded".
- Chat: a paired device receives only the trailing run of messages already exchanged with that same device, plus the new prompt. Nothing written under Local only, for this computer or for another device is sent to it; this computer still gets the whole stored conversation. The empty-chat text and a banner say so.
- The status bar's Attention button has the fixed name "Pairing open"; the countdown is visible but hidden from screen readers.
- Windows firewall notice: the rule is read with one PowerShell query (not localized netsh text), a read that fails claims nothing, a daemon the app did not start is neither checked nor allowed, domain networks are named, and Allow replaces only this program's own rule.
- Backend: the hold survives a Sharing change and revocations cross it (see E5 above); a refusal only the pinned key's holder can send ends a dial instead of trying the next address; IPv6 candidates are not dialled from an IPv4 endpoint; a paired device's `finish_reason` is capped at 32 characters.

## Round 2 and 3 fixes (2026-10-22, working tree): unit evidence only

A second review (18 desktop findings) and a mesh security round changed more of what the app shows; none is in a packaged build yet. Commands and counts: `docs/VERIFICATION.md` (round 2 and round 3 entries).
- Windows firewall read: both PowerShell reads keep their errors and the script throws anything but a not-found error before `end`, so a failed read never reads as "no rule". Only the script text is tested; it has not run on Windows. A daemon the app started counts as its own only while it runs (`spawned && !exited`); after it exits the notice shows the adopted message and Allow refuses.
- A store whose last read failed is retried within 5 s (always-read or already-polled stores only). Before the first read of a busy service a section shows "Loading…", not its empty state, and no busy banner.
- A failed privacy read counts as not known in Devices (Permissions, readiness, "Can run there": "groups or privacy mode not known") and in Settings › Privacy, which keeps its controls mounted and inert and reads "Current mode: not known while the background service is not running."
- Inspector and Run panel live values (Models State and Locations, Chat's loaded model, Devices Performance) read "not refreshed" while the service is busy or stale. Devices Free memory reads "Not reported live".
- Accessibility: the status bar's Service and Network rate are named groups ("Service: Running", "Network rate"); its items no longer remount when a tip appears; the engine's loading seconds are hidden from screen readers and given in the tip; focus moves to the outcome after Allow on private networks succeeds; the Chat context hint is the composer's accessible description.
- Chat copy: "{device} gets only the messages exchanged with it since you last used another destination; earlier messages are not sent with this prompt." (the earlier "stay on this computer" claim is gone).
- Round 3 (daemon): a refusal reached before the other device has proved its key on the control stream reads `peer_unauthorized`. So a device that revoked this computer shows `peer_unauthorized`, not `peer_revoked`, on a new dial, and "Disconnected by <device>" (`last_error.code` `peer_held`) appears only when the holder runs a protocol minor 1 build; a minor-0 holder (every build committed so far, including the 593d4ea Windows installer) closes before its Hello and reads `peer_unauthorized`.
