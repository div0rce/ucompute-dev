## Status rules (enforced by `scripts/validate_registry.py`)
- Allowed: `NOT_STARTED`, `IN_PROGRESS`, `BLOCKED`, `IMPLEMENTED_UNVERIFIED`, `VERIFIED`, `INFEASIBLE_WITH_EVIDENCE`.
- `VERIFIED` = every acceptance criterion in that row demonstrated, evidence path recorded, commit hash recorded, all dependencies `VERIFIED`. No mass-marking.
- `INFEASIBLE_WITH_EVIDENCE` is not done; it needs a written determination with sources.
- A claim from another agent or a chat summary is at most `IMPLEMENTED_UNVERIFIED` until you see the evidence yourself.

## Hard rules
- **Work never stops because a machine sleeps or a connection drops (owner, 2026-10-29, non-negotiable).** On the Mac every session holds a sleep-prevention assertion (`caffeinate -ims -w <session pid>`, set by the user-level SessionStart hook; start it yourself if `pgrep -lf "caffeinate -ims"` finds none) and every long command runs under `caffeinate -i`. Remote long jobs never depend on the SSH session: `setsid nohup` with pid files on Linux, a WMI-created process (`Invoke-CimMethod Win32_Process Create`) on Windows, `nohup caffeinate -i` on a Mac. A closed lid still sleeps a MacBook; only the owner changes that.
- No mocked or simulated inference presented as real. Synthetic fixtures must be labelled as such in the test name and evidence.
- **Single-host multiprocess tests are labelled `SINGLE-HOST`** in test names, evidence and docs. They never satisfy a two-machine criterion (F-03-01, F-03-02, Gate D). Two independent physical machines are required.
- Never expose llama.cpp `rpc-server` (or any unauthenticated service) beyond loopback. Cross-machine traffic goes only through UCompute's authenticated, encrypted transport.
- Default API bind is `127.0.0.1`. No public ports, no paid services, no real-money settlement, no releases without explicit owner approval (spec section 4).
- No silent model, quantization, or privacy-mode substitution.
- Unified compute credits with contributor consent (D-019, spec §26.5): no code path may charge for, or require a purchase or a UCompute-operated account or service for, Run, private Mesh or self-hosted operation. None may charge for, or require a purchase or a UCompute-operated account for, joining the network, contributing or donating. No credits for computing for yourself: no code path may credit a user for workloads they originate or for execution on resources under the same beneficial ownership or control (separate accounts or device ids are not independence); credits are earned only for verified, authorized work for an eligible independent consumer under a compensated arrangement. No code path may allocate contributed capacity beyond its owner's explicit sharing mode (default off; private, donate, share for credits), trusted-access allowlist and limits; donate-only capacity never serves credit-funded requests. A request under an owner's trusted-access allowlist (authenticated identity, scoped to that provider) spends, earns and pays fees of zero, and no free request becomes paid without the requester's explicit authorization or bounded paid-fallback policy. Credits are one balance, issued only through confirmed purchases, provider compensation transferred from customer-funded spends, or budgeted labelled grants, never requiring cryptocurrency or blockchain (none is implemented at this stage), and neither transferable between users nor redeemable for cash before the F-07-11 gates. No production payments, contributor payouts or real-money settlement without explicit owner authorization (spec §4, B-006). Self-hosted credit accounting, cross-network settlement, and ledger federation are outside the current committed scope. Their architecture and economic rules remain undecided. Do not implement them.
- Never copy GPL/AGPL code (including historical ex-exo or KoboldCpp code). Verify the exact upstream revision and component license; the current Exo tree has a different license recorded in the 2026-10-18 research refresh. See ADR-0001.
- Never fabricate benchmark numbers. Results live in `benchmarks/results/` with hardware manifest, command line, versions.
- Preserve existing code; inspect before editing.
